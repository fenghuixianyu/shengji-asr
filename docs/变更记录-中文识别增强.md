# 变更记录 · 中文识别增强（拼音问题修复）

> 本文记录一次**用户反馈 → 根因定位 → 代码修改 → 验证 → 还原方法**的完整过程，
> 便于他人复现，也便于日后需要时**回退到改动前**的行为。

---

## 一、用户反馈（原始问题）

使用「声迹」标准档（SenseVoice）做中文语音识别时，出现以下异常：

1. **短句「你好」被识别成拼音**：输出 `Lihao.` 之类的拼音串，而不是「你好」。
2. **句子中间也会偶发拼音**：例如「你好啊」被识别成 `Bunanba.`；
   「就不」被识别成 `就不an吧。` 这种中英/拼音混杂。
3. 同样一句话，**有时候能正常识别，有时候又不行**，表现不稳定。
4. 用户诉求：**主要用在中文**（其次英文），**不要拼音**；希望稳定增强中文效果。

复现样本（用户口述/自测）：

| 输入（中文） | 实际输出（异常） |
|---|---|
| 你好 | `Lihao.` |
| 你好啊 | `Bunanba.` / `你好哇` |
| 就不……吧 | `就不an吧。` |

---

## 二、根因定位

问题**不是**模型本身出错，而是 **sherpa-onnx 内置配置的默认值不适合中文短句**。

证据（反编译 `app/libs/sherpa-onnx-1.13.8.aar` 的 `OfflineRecognizerKt`）：

- App 走 `AsrEngine.load(type)` → `getOfflineModelConfig(type)` 拿内置配置。
- 标准档 `type = 15`（SenseVoice）在 AAR 里被硬编码为：

  ```kotlin
  OfflineSenseVoiceModelConfig(
      model = "sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/model.int8.onnx",
      language = null,                       // ← 自动语种检测
      useInverseTextNormalization = false,   // ← ITN 关闭
      qnnConfig = null,
  )
  ```

关键点：

1. **`language = null`（自动判别语种）**：SenseVoice 是多语种模型，`null` 表示让它自己猜。
   音频很短、或口音较重、或背景有噪声时，**很容易猜成日文 / 其他语种**，
   于是把中文音素按日文罗马字 / 拼音输出 —— 这就是 `Lihao.` / `い` 的来源。
2. **`useInverseTextNormalization = false`（ITN 关闭）**：不自动补标点、数字不规整。

> 结论：**强制指定中文 + 打开 ITN**，即可让中文短句稳定输出中文并自动带标点。

---

## 三、实测对照（改动依据）

用官方中文测试集与合成语音做了多组对照实验（`auto` vs `zh` vs `zh+itn`）：

- **长句**：`auto` 与 `zh` 结果几乎完全一致；`zh+itn` 额外补标点，更规整。
- **短句（关键）**：0.2~0.8 s 极短片段下，`auto` 会吐日文（`い`）或乱码；
  **`zh` 能稳定输出中文**，`zh+itn` 再补上标点。
- **英文无损**：`zh` 模式识别英文结果与 `auto` 完全一致，且 `zh+itn` 还给英文补了大写与标点。
- **示例**：
  - 「你好」1.36 s：`auto`→`你好`，0.2 s 切片时 `auto`→`い`，而 `zh`→`你` / `你好`。
  - 视频测试音频：`zh+itn` 输出「这是一个视频文件的语音测试，请把视频里的声音自动转成文字。…」

**结论：强制 `language="zh"` 不损失英文，且显著稳定中文短句。**

## 四、实际修改（改了什么）

**唯一改动文件**：`app/src/main/java/com/shengji/asr/AsrEngine.kt`

1. 新增 import：`com.k2fsa.sherpa.onnx.OfflineModelConfig`
2. `load(modelType)` 中，取到内置配置后先调用 `tuneForChinese(...)` 再构造识别器。
3. 新增私有方法 `tuneForChinese`，按模型类型覆写配置：

```kotlin
private fun tuneForChinese(modelType: Int, modelConfig: OfflineModelConfig) {
    when (modelType) {
        AsrModels.SENSE_VOICE_2024 -> modelConfig.senseVoice?.let { sv ->
            sv.language = "zh"                          // 强制中文, 不再自动猜语种
            sv.useInverseTextNormalization = true        // 打开 ITN: 标点 + 数字规整
            Log.i(TAG, "tune sense-voice: language=zh, itn=true")
        }
        AsrModels.FUNASR_NANO -> modelConfig.funasrNano?.let { fn ->
            fn.language = "zh"
            fn.itn = true
            Log.i(TAG, "tune funasr-nano: language=zh, itn=true")
        }
    }
}
```

- 标准档（`type=15`）与高精度档（`type=46`）**都**被强制为中文 + ITN。
- 其他档位（未内置）保持原样，不做任何覆写。
- **不改变模型文件本身**，只改运行期配置。

### 修改前 / 修改后（load 函数核心片段）

修改前：

```kotlin
val config = OfflineRecognizerConfig(
    featConfig = getFeatureConfig(sampleRate = SAMPLE_RATE, featureDim = 80),
    modelConfig = requireNotNull(getOfflineModelConfig(type = modelType)) {
        "unknown model type $modelType"
    },
)
```

修改后：

```kotlin
val modelConfig = requireNotNull(getOfflineModelConfig(type = modelType)) {
    "unknown model type $modelType"
}
tuneForChinese(modelType, modelConfig)
val config = OfflineRecognizerConfig(
    featConfig = getFeatureConfig(sampleRate = SAMPLE_RATE, featureDim = 80),
    modelConfig = modelConfig,
)
```

## 六、如何还原（回退到改动前）

若需恢复「自动语种检测 + ITN 关闭」的原始行为：

1. 用备份文件覆盖 `AsrEngine.kt`（若保留了备份）。
2. 或手动删除 `load()` 中的 `tuneForChinese(modelType, modelConfig)` 调用，
   并删除 `tuneForChinese` 方法与 `OfflineModelConfig` 的 import。
3. 重新构建：`./gradlew assembleStdDebug assembleFullDebug`。

> 改动是**可逆且隔离**的：只涉及一个文件、一个私有方法，删除调用即可回到原行为。
