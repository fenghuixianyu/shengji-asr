# 变更记录 · 识别语言模式（应用内切换）

> 本文记录一次**用户反馈 → 方案取舍 → 代码修改 → 上机验证 → 还原**的完整过程。
> 这次改动把原先「写死中文优先」的做法，升级为**应用内可切换的三档语言模式**，
> 同时保留「默认中文优先」的体验。

---

## 一、用户反馈（原始问题）

在使用「声迹」的过程中，用户提出两类相互拉扯的诉求：

1. **英文被拉成中文**：目前强制中文解码（`language=zh`），遇到英文素材时，
   有些英文单词会被识别成中文（例如把英文人名 / 术语读成中文谐音）。
2. **想要按场景切换**：希望 App 内能选不同模式，而不是只有一个写死的行为。
   用户具体提了三种：

   | 用户描述 | 期望行为 |
   |---|---|
   | 英文比较敏感的模式 | 英文素材优先，别把英文读成中文 |
   | 中文优先的模式 | 现状，中文最稳（默认） |
   | 日、韩、粤等语言一并的模式 | 恢复模型原生的自动判别，覆盖更多语种 |

3. 用户原话：**「如果不能实现应用内调节的话，那就算了。」**
   —— 即：能做就做，做不了不强求。

---

## 二、方案取舍

### 结论：可以实现，且已实现

sherpa-onnx 的 SenseVoice 与 FunASR-Nano **都支持在构造识别器时指定语种**，
所以「语言模式」本质上就是**给识别器传不同的 `language` 参数**。
代价是：语种是**构造期**写进 native 配置的，**切换必须重建识别器**。

### 三种模式的实现

| 模式 | `language` 传值 | 说明 |
|---|---|---|
| 中文优先（默认） | `"zh"` | 强制中文，短句稳定、不出拼音 |
| 英文优先 | `"en"` | 强制英文，英文最稳，中文会明显退化 |
| 多语种自动 | `""`（空串） | 恢复模型原生 auto 判别，中/英/日/韩/粤 |

### 关键坑：FunASR-Nano 的 `language` 不是语言码

- **SenseVoice** 的 `language` 吃标准语言码：`auto / zh / en / ja / ko / yue`，
  空串即 auto。
- **FunASR-Nano** 的 `language` 是**自由文本**，会被拼进 prompt
  （`语音转写成X：`）。如果直接传 `"zh"`，prompt 会变成「语音转写成zh：」，
  模型看不懂。所以必须**映射成中文词**：

  | languageCode | FunASR-Nano 实际传入 |
  |---|---|
  | `"zh"` | `"中文"` |
  | `"en"` | `"英文"` |
  | `""` | `""`（不带语言约束，即原生「语音转写：」） |

  证据：反编译 `sherpa-onnx-1.13.8.aar`，`funasr_nano_impl.cc` 的 `BuildUserPrompt()`
  会把 `language` 直接拼进 prompt；而 `sense_voice` 侧有枚举校验。

## 三、实际修改（改了什么）

**改动文件：4 个**（全部在 `app/src/main/java/com/shengji/asr/`）

### 1. `AsrEngine.kt`（整文件重写要点）

- `load(modelType)` → `load(modelType, languageCode = LANGUAGE_AUTO)`，新增第二参数。
- 新增 `loadedLanguage` / `currentLanguage`；幂等判断改为 **`modelType` 且 `languageCode`**
  两个条件都相同才复用（任一变化就重建）。
- 新增常量 `LANGUAGE_AUTO = ""`。
- `tuneForChinese(...)` → 改名 `tuneForLanguage(modelType, languageCode, modelConfig)`：
  - SenseVoice：`sv.language = languageCode`，ITN 恒 `true`。
  - FunASR-Nano：`fn.language = funAsrNanoLanguage(languageCode)`（中文词映射），ITN 恒 `true`。
- 新增私有方法 `funAsrNanoLanguage()`：`"zh"→"中文"`、`"en"→"英文"`、其他→`""`。
- 日志格式改为带引号，便于区分空串：
  `load offline model type=15 language='zh'`。

### 2. `AsrModels.kt`

- 新增 `data class LanguageMode(id, displayName, tagline, languageCode, description)`。
- 三个实例：`langChinese`（`zh`，**默认**）、`langEnglish`（`en`）、`langAuto`（`""`）。
- 新增 `languages: List<LanguageMode>`、`defaultLanguage = langChinese`。

### 3. `AsrViewModel.kt`

- `AsrUiState` 新增 `languageId` / `languageName`。
- `init` 里 `engine.load(modelType = ..., languageCode = AsrModels.defaultLanguage.languageCode)`。
- 新增 `currentLanguage()`、`selectLanguage(mode)`、`reloadRecognizer(...)`；
  `selectModel` 也改走 `reloadRecognizer`，统一模型 / 语言的重建路径。
- `busy` 或 `recording` 时切换会报错：**「请先停止当前任务再切换语言」**。

### 4. `ui/AsrApp.kt`

- 顶栏副标题：`本地离线 · ${state.modelName} · ${state.languageName}`。
- `ModelSelector` 下方插入 `LanguageSelector`：3 个 `FilterChip`
  （中文优先 / 英文优先 / 多语种自动），选中色用 `secondaryContainer`；
  下方显示当前模式的 `description`。
- 新增 import `androidx.compose.material.icons.rounded.Language`。
- LoadingBanner 文案改为「正在切换档位 / 语言模式, 请稍候…」。

> **未改动**：模型文件、导出逻辑（TXT / SRT）、界面其它区域。

## 四、上机验证

设备：Android 模拟器 `emulator-5556`（`RE_API33_D`，x86_64，API 33，
1080x2340 @ 440dpi，4 GB 内存）。日志过滤 `ShengjiAsr`。

### 标准档（SenseVoice，`type=15`）

| 模式 | 测试素材 | 结果 |
|---|---|---|
| 中文优先（默认） | `zh_official.wav` | `[00:00:00 - 00:00:05] 开饭时间早上9点至下午5点。` 纯中文无拼音 |
| 英文优先 | `en_official.wav` | `The tribal chieftain called for the boy.` / `And presented him with 50 pieces of gold.` 准确 |
| 多语种自动 | `yue_official.wav` | `呢几个字都表达唔到，我想讲嘅意思。` 粤语正确识别 |

日志证据：

```
load offline model type=15 language='zh'  → tune sense-voice: language='zh', itn=true
load offline model type=15 language='en'  → tune sense-voice: language='en', itn=true
load offline model type=15 language=''    → tune sense-voice: language='', itn=true
```

### 高精度档（FunASR-Nano，`type=46`）

| 验证项 | 结果 |
|---|---|
| 默认加载（中文优先） | ✅ `load offline model type=46 language='zh'` → `tune funasr-nano: language='中文', itn=true` |
| 切英文优先 | ✅ `language='en'` → `tune funasr-nano: language='英文'` |
| 切多语种自动 | ✅ `language=''` → `tune funasr-nano: language=''` |
| 端到端导入 `zh.wav` | ✅ 识别出 1 段 |
| 导出带时间戳 TXT | ✅ 文件内容 `[00:00:00 - 00:00:05] 菜饭时间早上九点至下午五点。` |

### 用户反馈 bug 回归（短句「你好」出拼音）

用 Windows TTS（`Microsoft Huihui Desktop`，16k 单声道）合成一组短句，
在**中文优先**与**多语种自动**两种模式下测试，**全部正确**，未复现拼音：

| 输入 | 输出 |
|---|---|
| 「你好。」 | `你好。` |
| 「你好啊。」 | `你好哇。` |
| 「你好，你好。」 | 两段 `你好。` |
| 「你好，我想问一下这个功能到底要怎么用啊？」 | `你好。` + `我想问一下这个功能到底要怎么用啊？` |
| 「今天天气不错，我们出去走走吧。」 | 两段正确 |

## 五、三种模式效果对比（经验结论）

| 模式 | 中文 | 英文 | 日 / 韩 / 粤 | 适用场景 |
|---|---|---|---|---|
| **中文优先**（默认） | 最稳 | 尚可，偶被拉成中文 | 不保证 | 绝大多数中文素材；中英混说 |
| **英文优先** | 明显退化 | 最稳 | 不保证 | 纯英文素材 |
| **多语种自动** | 尚可，短句偶有误判 | 好 | 支持 | 语种混杂 / 非中文素材 |

**建议**：默认留在**中文优先**；只有整段英文素材才切「英文优先」；
遇到日 / 韩 / 粤或语种混杂，再切「多语种自动」。

## 六、如何还原

### 还原到「写死中文优先」（本次改动之前的状态）

1. `AsrEngine.kt`：把 `load` 的第二参数去掉，恢复 `load(modelType)`；
   把 `tuneForLanguage(...)` 换回 `tuneForChinese(...)`，内部固定 `language = "zh"`。
2. `AsrModels.kt`：删除 `LanguageMode` 与 `languages` / `defaultLanguage`。
3. `AsrViewModel.kt`：删除 `languageId` / `languageName` 字段与
   `selectLanguage` / `currentLanguage`；`selectModel` 恢复直接 `engine.load(spec.recognizerType)`。
4. `ui/AsrApp.kt`：删除 `LanguageSelector` 与相关 import，副标题去掉 `languageName`。
5. 重新构建：`./gradlew assembleStdDebug assembleFullDebug`。

### 只回退某一档的行为

- 若只想让默认档回到「自动语种」，把 `AsrModels.defaultLanguage` 改为 `langAuto` 即可
  （不改引擎代码）。

> 改动**可逆且隔离**：只涉及上述 4 个文件，不触碰模型与导出逻辑。
